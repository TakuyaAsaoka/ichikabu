# 総務省統計局の公表予定を取り込む（Issue #64）

全体設計書 §2.1 が「総務省統計局は読んでよい」と決めた（PR #63）。ここはその実装の設計。

消費者物価指数の公表予定 XML を手で実行するスクリプトで読み、全国の月次だけを市場イベントとして登録する。年12件を手で写す作業が消える。

## 1. 決めたこと

Issue #64 の「残る判断」8件の結論。

| # | 判断 | 結論 | 理由 |
|---|---|---|---|
| 1 | 置き場所 | `server/scripts/import-stat-schedule.ts`（`pnpm import:stat` で手で実行） | 運用者は1人。管理UIのボタンは今は要らない |
| 2 | 取りに行く間隔 | 決まった間隔での自動実行は作らない | XML は16ヶ月先まで載っているので月1回で足りる。自動実行にするかどうかは Issue #107 で決める（本番が Netlify に決まったため詰められる状態になった） |
| 3 | 東京都区部 | 入れない。全国だけ | 株式市場に効くのは全国のほう。合わせると年24件になり、カレンダーの1日2件の枠を食う |
| 4 | どの統計 | 消費者物価指数だけ | 他9本は中身を確かめていない。使いたくなったときに1本ずつ確かめる |
| 5 | 重複の防ぎ方 | 名称が既にあれば入れない | 名称に対象月が入る（`消費者物価指数（2026年1月分）`）ので公表回ごとに1つに定まる。`src/db/seed-event.ts` と同じ判定 |
| 6 | 公表日が変わったとき | 開始日と時刻だけ更新し、変えた内容を実行時に出す | 取り込みの一番の動機。短縮ラベル・重要度・備考は運用者が手で直す列なので上書きしない |
| 7 | 短縮ラベル・重要度 | `日本CPI` / `2` | 幅7で上限（全角5文字＝幅10）に収まる。米CPI が2なので揃える |
| 8 | 対象 | `market: JP` | 米CPI が `GLOBAL` なのは日本株にも効くから（`seed-event.ts`）。日本のCPI は米国株の保有者には効かないので `JP` |

出典は表示名 `総務省統計局`、URL `https://www.stat.go.jp/data/cpi/`。全体設計書 §2.1 の条件4は、この2つを入れれば満たせる。

## 2. XML の読み方

配信元は `https://www.stat.go.jp/data/kouhyou/e-stat_cpi.xml`（2026-08-12 に HTTP 200・58,970 バイト）。

### 2.1 文字コード

**UTF-16LE。** 先頭の BOM が `FF FE` で、宣言は `<?xml version="1.0" encoding="UTF-16" ?>`。

`TextDecoder("utf-16le")` でバイト列を文字列に直す。BOM は既定で落ちる。

`curl` で落として `iconv` で UTF-8 に直す手は使えない。**宣言が `UTF-16` のまま残るため、XML パーサが `encoding specified in XML declaration is incorrect` で弾く。**

### 2.2 取り出し方

XML パーサのライブラリは足さない。**正規表現で必要な3つを取り出す。**

```
<class_1 name="全国">                 ← 区分。全国だけを使う
  <class_2 name="2026年1月分">        ← 対象期。YYYY年M月分 の形だけを使う
    …<class_5>
      <release_year> / <release_month> / <release_day>
      <release_hour> / <release_minute>
```

`class_3` `class_4` `class_5` は `name` が空のまま入れ子になっているだけなので、`class_2` の中身をそのまま次の正規表現に渡せば飛ばせる。

ライブラリを足さない理由は、必要な形が上の3つだけで20行に収まるため。**総務省が機械で作っている決まった形に合わせた読み方なので、属性が増えたり `<![CDATA[` が入ったりすると壊れる。** そのときにライブラリを足す。この見込みはコードのコメントにも書く。

### 2.3 月次かどうかの判定

`class_2` の `name` が `YYYY年M月分` の形かどうかで決める。この形でないものは落ちる。

| 落ちるもの（全国・2026-08-12 時点） |
|---|
| 2025年平均 |
| 2025年度平均 |
| 2026年平均 |
| 2025年基準による指数　遡及結果（2025年1月分～2026年6月分）及び接続指数 |

<!-- 上の表は統計の名前をそのまま写している。言い換えると出典の名前と合わなくなる。jargon-ok -->

全国は全19件のうち15件が月次（2025年12月分・公表 2026-01-23 〜 2027年2月分・公表 2027-03-19）。公表時刻は月次すべて 8:30。

### 2.4 作られる値

`class_2 name="2026年1月分"`、公表日時 2026-02-20 8:30 のとき。

| 列 | 値 |
|---|---|
| title | 消費者物価指数（2026年1月分） |
| shortLabel | 日本CPI |
| market | JP |
| startDate | 2026-02-20 |
| endDate | null（単日） |
| time | 08:30 |
| importance | 2 |
| note | null |
| sourceName | 総務省統計局 |
| sourceUrl | https://www.stat.go.jp/data/cpi/ |

公表日時は日本時間そのままで、FOMC・米CPI のような時差の換算は要らない（全体設計書 §4.1 は日付・時刻を日本時間で入れると決めている）。

## 3. ファイルの分け方

| ファイル | 中身 |
|---|---|
| `server/app/stat-schedule.ts` | 取得（`fetch` と UTF-16 の読み取り）と変換（XML の文字列 → `EventInput[]`）。変換は引数だけで結果が決まる関数にする |
| `server/app/stat-schedule.test.ts` | 変換のテスト。**ネットワークには出ない**。入力は実物から取った2件ぶんの入れ子 |
| `server/scripts/import-stat-schedule.ts` | 取得 → 登録 → 何を入れて何を変えたかを出す |
| `server/src/db/write.ts` | `upsertMarketEvents` を足す（下記） |
| `server/src/db/seed-event.ts` | 開発用データに日本CPI を足す |

`app/` に置くのは、`app/bulk-event-input.ts` と同じ理由。`"use server"` を付けない素のモジュールにすれば Vitest から読み込める。将来ここを管理UIのボタンから呼ぶことになっても置き場所を変えずに済む。

## 4. 登録と更新（`upsertMarketEvents`）

`src/db/write.ts` に足す。1つの取り引きで次を行う。

1. 渡された名称の行を読む（`title` で引く）
2. 無い名称は登録する
3. ある名称は、開始日か時刻が違うときだけ更新する。更新するのは `start_date` と `time` の2列だけ
4. 「入れた件数」と「変えた行の一覧（名称・前の日時・後の日時）」を返す

`createEvents`（貼り付け用）を使い回さない理由は、あちらが登録しかせず、行番号付きのエラー文を返す形になっているため。取り込みには行番号が無く、更新も要る。

名称で引く形にできるのは、`title` に対象月が入っていて公表回ごとに1つに定まるから。**`event` に一意の制約は無いので、DB が重複を止めてくれるわけではない。** 同じ名称の行が手で2件入れられていたら、更新が当たるのは1件だけで、もう1件は古い公表日のまま残る。運用者が1人でこの経路しか使わない前提で、制約は足さない。
