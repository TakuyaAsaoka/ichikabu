# 取り込んだ公表予定を非アクティブにする（Issue #72）

Issue #64（PR #69）で作った取り込みは、XML に載っている回しか見ていない。DB にあって XML に無い行はそのまま残る。中止・延期で来なくなった予定がカレンダーに残り続ける。

`event` にアクティブかどうかの列を足し、**これからの回で公表予定から消えたもの**を取り込みが非アクティブにする。行は消さない。

## 1. 決めたこと

Issue #72 の「残る判断」4件の結論。

| # | 判断 | 結論 | 理由 |
|---|---|---|---|
| 1 | 非アクティブにする行の見分け方 | **取り込みが名づける名称の形**（`^消費者物価指数（[0-9]{4}年[0-9]{1,2}月分）$`）に当たる行 | §2 |
| 2 | 管理UIの表示 | イベント一覧に `【非アクティブ】` を出す | 非アクティブの行を見られる場所が他に無い。旗を立てて画面に出さないのは、立てていないのと同じ。前例として、出典の表示名が空の行も同じ一覧で分かるようにしている（編集・削除 設計書 §3.1） |
| 3 | `openapi.yaml` | 変えない | 非アクティブの行を返さないだけで、レスポンスに列は要らない。iOS 側の変更も無い |
| 4 | `active` の既定値 | `boolean NOT NULL DEFAULT true` | 手で入れる行・開発用データ・既にある行がすべてアクティブになる。他の値だと既存行の移行が要る |

## 2. なぜ出典URLで見分けないか

`event` に「取り込みで入った行」の印は無い。候補は2つあった。

| 案 | 絞り方 |
|---|---|
| A | `source_url = 'https://www.stat.go.jp/data/cpi/'` |
| B | 名称が取り込みの形に当たる（採用） |

**決め手は XML の実測。** 取り込みは全国（`AREA`）の月次（`MONTHLY`）だけを読む。XML にはそれ以外も載っている。

| XML に載っているが取り込まないもの | 公表日が今日（2026-08-12）以降 |
|---|---|
| 東京都区部（中旬速報値）18件 | 12件（2026-08-28 〜 2027-03-26） |
| 全国の年平均・年度平均 | 1件（2026年平均 → 2027-01-22） |

運用者がこれらを手で登録するとき、出典URLは取り込みと同じ `https://www.stat.go.jp/data/cpi/` しか無い（CPI の出典ページは全国も東京都区部も同じ）。**A案はこれらを毎月非アクティブにする。**

Issue #72 の方針は「これからの回について、XML に**載っていない**ものは無くなったと扱う」である。これらの行は載っている。**方針の適用条件を満たさない行に旗を立てることになる。** しかも運用者が旗を戻しても、次の取り込みでまた落ちる。

B案の代償は「運用者が取り込み済みの行の名称を手で書き換えると、古い行が非アクティブにならず同じ回が2件並ぶ」。ただしこの重複は #72 の前から起きる（`upsertMarketEvents` は名称だけで突き合わせるため、名称を直した時点で次の取り込みが新規登録する）。公表予定の取り込み設計書 §4 が明記のうえ受け入れている既存の問題で、非アクティブ化の範囲で掃除する話ではない。

**失敗したときの向きが逆であることを採った。** B案の失敗は旗が立たない（＝今と同じ）。A案の失敗は、実際に公表される回がカレンダーから消える。

### 名称の形をどこに置くか

`app/stat-schedule.ts` に `STAT_TITLE_PATTERN` として置き、`upsertMarketEvents` に引数で渡す。名称を組み立てる部品（`STATISTIC_NAME` と月次の形）から作るため、**統計名や対象期の形を変えれば一緒に変わる**。書き写した正規表現が古いまま残って、非アクティブ化が黙って0件になることを防ぐ。

`src/db/write.ts` に直接書かないのは、DB を書く層が取り込みの都合を持たないようにするため。

## 3. 非アクティブにする条件

`upsertMarketEvents` の同じ取り引きの中で、登録・更新のあとに2つ実行する。

```
1. アクティブに戻す: 公表予定に載っている名称の行で、非アクティブのもの
2. 非アクティブにする: 次の4つをすべて満たす行
   - アクティブである
   - 名称が取り込みの形に当たる
   - 開始日が今日（日本時間）以降
   - 公表予定から作った名称の並びに無い
```

- **アクティブに戻す処理を、公表日時の更新に混ぜない。** あちらは公表日時が変わった行だけを返す形になっている。日時が変わらないまま戻ってきた回を混ぜると、前後が同じ「変更」が出る
- **今日は日本時間で決める**（`(now() AT TIME ZONE 'Asia/Tokyo')::date`）。DBの時間帯そのままの `CURRENT_DATE` だと、日本時間の朝9時までは前日と判定され、公表済みの回まで対象に入る
- **渡された並びが0件なら何もしない。** XML の形が変わって1件も読めなかったときに、取り込み済みの回が全部消えるのを防ぐ
- **一度に非アクティブにする回が2件以上なら投げ、取り引きごと巻き戻す**（Issue #107 で足した）。上の0件の守りは、XML が**全部**読めなくなったときにしか効かない。一部だけ読めなくなる形の変化が実在し、そのとき読み落とした回がここに流れ込む。中止・延期は1回ずつ起きるものなので、まとめて消えるのは読み落としとみなす。→ 取り込みの設計書 §7

## 4. 読み出し

`GET /events` は `active` が真の行だけを返す。**開始日は見ない。** 非アクティブのまま公表日を過ぎた行（＝中止された回）も出さないため、書き込み側で開始日を見て、読み出しは `active` 1つで絞れる形にしてある。

管理UIの一覧は全件を出したまま、非アクティブの行に `【非アクティブ】` を付ける。絞り込み・並べ替え・アクティブに戻すボタンは付けない（運用者は1人、対象は年12件）。非アクティブの行が要らなくなったら、既にある削除で消せる。

## 5. 実行時に出すもの

```
非アクティブにした: 1 件
  - 消費者物価指数（2099年1月分）
```

アクティブに戻した回は出さない。運用者がすることが無いため。

## 6. テスト

| テスト | 何が壊れたら赤くなるか |
|---|---|
| `app/stat-schedule.test.ts` `STAT_TITLE_PATTERN` | 取り込みが作る名称が形に当たらなくなる・年平均や東京都区部の名称が形に当たる |
| `src/db/write.test.ts` 公表予定から消えたこれからの回 | 非アクティブにしない・行を消す |
| 同 公表済みの回 | 開始日を見ずに過去の回まで非アクティブにする |
| 同 また載ればアクティブに戻る | 公表日時が同じときに戻し損ねる |
| 同 取り込みが名づけない名称の行 | 出典URLで絞る形に戻す（東京都区部・年平均が消える） |
| 同 空の並び | 0件ガードを外す（取り込み済みの回が全部消える） |
| 同 2件以上の非アクティブ化（Issue #107） | 上限を外す（読み落としたこれからの回がまとめて消える）・投げる場所を取り引きの外に出す（巻き戻らない） |
| `app/api/events/route.test.ts` 非アクティブのイベント | 読み出しで `active` を見ない |

上の8件はすべて、対応する実装を壊して赤くなることを実測で確かめてある。
