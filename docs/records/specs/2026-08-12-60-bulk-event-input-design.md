# イベントの一括登録 設計書

- 対応 Issue: [#60 イベントを貼り付けでまとめて登録する](https://github.com/TakuyaAsaoka/ichikabu/issues/60)
- 根拠: [全体設計書](2026-08-02-1-ichikabu-design.md)（§2 やらないこと・§4.2 対象の3列）、[管理UI設計書](2026-08-09-6-admin-ui-design.md)（§3 画面構成・§5 登録の失敗の扱い・§12 openapi.yaml の扱い）、[イベント登録フォーム設計書](2026-08-09-7-admin-event-form-design.md)、[イベントの編集・削除 設計書](2026-08-11-43-edit-event-design.md)（§4.1 共通部品）

## 1. 目的と結論

**スプレッドシートで作った複数行を管理UIに貼り付けて、まとめて登録できるようにする。** イベントは今1件ずつフォームに入れるしかない。決算発表日は保有銘柄数 × 年4回あり、経済指標も年に数十件ある。

| 項目 | 決定 |
|---|---|
| 入力の形 | `<textarea>` への貼り付け。タブ区切り10列（→ §2） |
| 対象の書き方 | `market:GLOBAL` / `stock:JP:7203` / `theme:半導体`。銘柄はティッカー、テーマは名前で書く（→ §3） |
| 失敗したときの扱い | 全件を1つの取り引きにまとめ、1行でも失敗したら1件も入れない。エラー文に行番号を付ける（→ §4） |
| 置き場所 | 管理画面の「イベントを登録」の下（→ §5） |
| 重複の判定 | やらない（→ §9） |
| ICS の取り込み | 機能として作らない。人が使い捨てのコマンドで貼り付けの形に直す（→ §9） |

## 2. 行の形

タブ区切りの10列。並びは `EventForm` の入力欄と同じにする。運用者が画面の並びと突き合わせられるため。

| 列 | 中身 | 例 | 空にできるか |
|---|---|---|---|
| 1 | 名称 | トヨタ自動車 2027年3月期 第1四半期決算 | × |
| 2 | 短縮ラベル | 7203決算 | × |
| 3 | 対象 | `stock:JP:7203`（→ §3） | × |
| 4 | 開始日 | 2026-08-04 | × |
| 5 | 終了日 | | ○ |
| 6 | 時刻 | 21:30 | ○ |
| 7 | 重要度 | 3 | × |
| 8 | 補足 | | ○ |
| 9 | 出典URL | https://global.toyota/... | ○ |
| 10 | 出典の表示名 | U.S. Bureau of Labor Statistics | ○ |

- 行の区切りは `\r?\n`。改行コードの違うところからコピーしても同じに読む
- 落とすのは**末尾の空行だけ**。貼り付けの末尾に改行が入るため。途中の空行は落とさず、そのまま列数のエラーにする。全部を無条件に飛ばすと、貼り付けた文字列の途中に空行が1つでもあるだけで、以降のエラーの行番号がテキストエリアの行番号より小さくなる
- 列が10個でない行はエラーにする。多い場合も少ない場合も同じ扱い
- 空欄を `null` に読み替える規則は1件ずつのフォームと同じ（`app/event-input.ts` の `toNullable`）。空文字のまま date・time 列に渡すと、制約違反ではない型変換エラーで500になる
- 名称・短縮ラベル・開始日は空にできない。DB の `notNull` は空文字を弾かず、1件ずつのフォームを守っている `<input required>` も貼り付け経路には効かないため、`toEventInputs` の中で空文字を判定する

**CSV にはしない。** 引用符とカンマの扱いが要る。スプレッドシートからのコピーはタブ区切りになるため、タブなら分けるだけで済む。

## 3. 対象の書き方

対象の3列（`market` / `theme_id` / `stock_id`）はちょうど1つだけが埋まる（全体設計書 §4.2）。1件ずつのフォームでは `<select>` が `market:JP` / `theme:12` / `stock:3` の形で出しており、`app/event-input.ts` の `toTarget` が3列に振り分けている。

貼り付けでは**IDではなくティッカーとテーマ名で書く**。

| 書き方 | 埋まる列 |
|---|---|
| `market:JP` / `market:US` / `market:GLOBAL` | `market` |
| `stock:JP:7203` | `stock_id`（`stock` の `market` + `ticker` で引く） |
| `theme:半導体` | `theme_id`（`theme` の `name` で引く） |

IDで書く案は採らない。決算発表日の一括登録では対象が銘柄になり、運用者が一覧を見てIDを調べてから貼ることになる。ティッカーは運用者が既に手元に持っている値である。

**銘柄は市場とティッカーの2つで引く。** `stock` の一意の制約は `(market, ticker)` の組で、ティッカーだけでは1件に定まらない。

引くための対応表は Server Action の中で `stock` と `theme` を1回ずつ読んで作る。行ごとに問い合わせない。

見つからないときはエラーにする（→ §4）。`market` / `stock` / `theme` のどれでもない書き方も同じくエラーにする。`market:` の値だけは対応表を引かず、生の値のまま DB に渡して `event_market_check` に判定させる。1件ずつの登録が既にそうしている（`src/db/write.ts` の `eventValues`）。

テーマ名にコロンが入っても読めるように、最初のコロンだけで種別と中身に分ける。

## 4. 失敗したときの扱い

**1行でも失敗したら1件も入れない。** 一部だけ入った状態は、何が入って何が入らなかったのかを運用者が確かめられない。貼り直せば二重に入る。

エラー文には行番号を付ける。

```
3行目: その銘柄は無い
7行目: 短縮ラベルは全角5文字まで
```

判定は2か所に分かれる。

| 段階 | 判定するもの | 場所 |
|---|---|---|
| 貼り付けた文字列を読むとき | 列の数、対象の書き方、ティッカー・テーマ名が実在するか | `app/bulk-event-input.ts` |
| DB に入れるとき | 日付・時刻の形、重要度の範囲、対象がちょうど1つ、短縮ラベルの幅 | `src/db/write.ts`（既存の `MESSAGES` と `tooLongLabel` がそのまま効く） |

**DB に入れる側は1行ずつ INSERT する。** まとめて1回の INSERT にすると、どの行が失敗したかが分からず行番号を出せない。貼り付ける行数はせいぜい数十で、1行ずつでも問題にならない。

行番号は `inputs` の添字（`index + 1`）そのまま。`app/bulk-event-input.ts` の `toEventInputs` は読めた行を1件ずつそのまま `EventInput` として積むため、`inputs` の並びは貼り付けた行の並びと1対1で一致する。

```ts
/**
 * まとめて登録の途中で失敗したことを表す。
 * 取り引きの中から投げると Drizzle が ROLLBACK する
 */
class BulkFailure extends Error {}

export async function createEvents(
  inputs: EventInput[],
): Promise<string | null> {
  try {
    await db.transaction(async (tx) => {
      for (const [index, input] of inputs.entries()) {
        const message =
          tooLongLabel(input.shortLabel) ??
          (await run(tx.insert(event).values(eventValues(input))));
        if (message) {
          throw new BulkFailure(`${index + 1}行目: ${message}`);
        }
      }
    });
  } catch (error) {
    // 途中で失敗したときの文言はここで取り出す。それ以外の例外は投げ直す
    if (error instanceof BulkFailure) {
      return error.message;
    }
    throw error;
  }
  return null;
}
```

`tx.rollback()` ではなく例外を投げる形にした。`tx.rollback()` は必ず例外を投げる仕組みで、`try` の外に出た時点で TypeScript は `failure` を「代入されているかもしれないし `null` のままかもしれない」としか絞り込めず、`catch` の中で握っている失敗の型が合わない。自前の `BulkFailure` に文言を持たせて投げれば、`catch` の中で `instanceof` を通すだけで型が絞り込める。

`run()` は制約違反を日本語にする既存の関数で、渡す問い合わせを取り引き側（`tx`）に差し替えるだけで使える。

## 5. 画面

管理画面（`/`）の「イベントを登録」の下に「まとめて登録」を置く。

```
イベントを登録
  [1件ずつのフォーム]

イベントをまとめて登録
  [textarea]
  [まとめて登録]
```

`<textarea>` の下に列の並びを短く出し、`placeholder` に見本の1行を入れる。**別ページにはしない。** 1件ずつの登録と並べたほうが、どちらを使うか選べる。

送信中の表示・エラーの表示は `app/form.tsx` の `ActionForm` に任せる（イベントの編集・削除 設計書 §4.1）。他の5つのフォームと同じ形になる。

成功したら `revalidatePath("/")` で一覧を新しくする。1件ずつの登録（`addEvent`）と同じ。

## 6. 作るもの

| ファイル | 中身 |
|---|---|
| `app/bulk-event-input.ts`（新規） | 貼り付けた文字列と対応表から `EventInput[]` を作る。エラーは文字列で返す |
| `app/bulk-event-form.tsx`（新規） | `<textarea>` と見本 |
| `app/actions.ts` | `addEvents` を足す。対応表を読み、`toEventInputs` を通し、`createEvents` に渡す |
| `src/db/write.ts` | `createEvents` を足す（→ §4） |
| `app/page.tsx` | 「まとめて登録」のセクションを足す |

`app/bulk-event-input.ts` の形。

```ts
/** ティッカー・テーマ名からIDを引くための対応表 */
type Lookup = {
  stocks: { id: number; market: string; ticker: string }[];
  themes: { id: number; name: string }[];
};

/**
 * 貼り付けた文字列を createEvents の入力にする。
 * 読めない行があれば、行番号を付けた日本語のエラー文を返す
 */
export function toEventInputs(text: string, lookup: Lookup): EventInput[] | string;
```

**戻り値を配列か文字列にする。** 成功と失敗を1つの型で表す。呼ぶ側は `typeof result === "string"` で分かれる。

`app/event-input.ts` と同じく `"use server"` を付けない素のモジュールにする。`app/actions.ts` は `next/headers` を使うため Vitest から読み込めない（イベント登録フォーム設計書 §5）。

## 8. 目視確認の手順

1. `pnpm dev` で起動し、サインインする
2. 「まとめて登録」に、市場のイベント1行と銘柄のイベント1行を貼って登録する
3. 一覧に2件増えることを見る
4. 2行目のティッカーを実在しないものに変えて貼り、「2行目: その銘柄は無い」が出ることと、**一覧が増えていないこと**を見る
5. 1行目の重要度を `9` にして貼り、「1行目: 重要度は1〜3」が出ることを見る

## 9. やらないこと

| やらないこと | 理由 |
|---|---|
| 重複の判定 | `event` に一意の制約は無く、同じものを2回貼れば2件入る。一覧で見えるうえ、消す手段（編集ページの削除）が既にある |
| ファイルの読み込み | 貼り付けで足りる。スプレッドシートからは貼り付けのほうが手数が少ない |
| 列の並びを変えられるようにする | 運用者は1人（全体設計書 §12）。並びが合わないときは貼る側を直せばよい |
| 登録できた件数の表示 | 成功したら一覧に戻り、増えた行がその場で見える |
| ICS を読み込む機能 | 効くのは BLS の CPI・雇用統計だけ（2年で46件）で、決算発表日には効かない。それでいて ICS の切り出しと `US-Eastern` → `America/New_York` の変換を作ることになる。ICS の値を入れたいときは、人が使い捨てのコマンドで日付を抜いて貼る（Issue #60 に手順と実測を残した） |
| ICS をプログラムで取りに行く | BLS が禁じている（`docs/reference/source-terms.md`）。全体設計書 §2 の「イベントの自動取得・スクレイピングはやらない」は動かさない |
| `openapi.yaml` への追加 | Server Action で完結し、自作のパスではない（管理UI設計書 §12） |
| 銘柄・テーマの一括登録 | 今回はイベントだけ。銘柄は決算月、テーマは名前だけで列が少なく、1件ずつでも手間が変わらない |
