# 出典の利用条件

イベントの日付を**どの出典で確かめてよいか**（「出典の可否」）と、**どう取ってよいか**（「取り方」）の判断を先に置き、その根拠になった条文を後ろに原文で残す。

## 出典の可否

**イベントの日付は、下の表で「使う」になっている出典でのみ確かめる。出典は必要になったときに1つずつ増やす。**

| 出典 | 可否 | 根拠・条件 |
|---|---|---|
| 各社のIRページ（決算発表予定の告知） | **使う** | 条件なし。発信者が投資家に広く知らせるために出している日付の転記 |
| 日本の府省（経済指標の公表予定） | **使う** | 公共データ利用規約（第1.0版）。商用可で、条件は出典の記載。内閣府・総務省・財務省が同じ規約を採っている（→ 下の「日本の府省」） |
| FRB（FOMC の日程） | **使う** | パブリックドメインで、商用を外す記述が無い。条件は出所の記載。日程は HTML にしか無いので手で登録する（→ 下の「FRB」） |
| BLS（米CPI・雇用統計の公表予定） | **使う** | パブリックドメイン。条件は出所の記載。エンブレムは登録商標なので使わない。`bls.gov` はプログラムからの取得を禁じているので、ブラウザで開いて写す（→ 下の「BLS」） |
| 日銀（決定会合の日程・公表予定） | 使わない | 商用目的の転載・複製は対象外で、事前に相談が要ると公表している。このアプリは広告で収益化する（→ [製品の決まり](product.md)）ので商用にあたる。出所を書いても使えるようにならない |
| JPX（決算発表予定日） | 使わない | xlsx で無償配信されているが、利用条件が商用目的の収集と二次利用を、有料の契約か JPX の許可がある場合を除いて禁じている。許可は求めていない（確認日 2026-08-14。Issue #44） |
| 株探・みんかぶ・Investing.com・TradingView など | 使わない | 各社の利用規約が情報の商用利用・第三者への提供を禁じている |

- **この表は許可の一覧ではなく、どの出典をどう判断したかの記録である。** 出典を増やすときは、①発信者の利用条件を読む ②条件を満たす手段を**先に**決める（出所の記載が条件なら、どの画面に出すかを決めてから使う）③表の可否と根拠を書き換える、の順で行う。②では DB の `event_market_source_check`（市場イベントは出典の名前が要る。`server/src/db/schema.ts`）も見直す。この制約は「市場イベントの出典はどれも記載が条件」を前提にしている（Issue #179）。記載の要らない出典を市場イベントに使うなら制約を緩め、記載の要る出典を銘柄・テーマのイベントに使うなら、その行の出典の抜けを止める手段を別に決める
- **出所の記載は `event.source_name` と `event.source_url` で満たす。** 名前とURLがそろった行だけがアプリに返り、iOS のシートに出る
- **企業ロゴは使わない。** 銘柄名・企業名を文字で出すのは事実を指すためで問題にならない
- **日付そのものは著作権で守られないとされるが、実際に効くのは各社の利用規約である。** 大量に丸写ししたことを不法行為と認めた判例があるので、「著作権が無い＝自由に写してよい」とは読まない。表はこの前提で作っている
- **代わりに登録できないものが残る。** 日銀の会合日程と、テーマに固有の出来事（政策・業界の発表。発信者ごとの条件をまだ読んでいない）。決算のように各社IRで確かめられる出来事は、テーマに寄せたテーマのイベントとして登録できる

**原文を残しているのは「使う」の出典のうち条文があるもの**（日本の府省・FRB・BLS）。「使わない」の出典は使っていないので原文が要る場面が無く、必要になったときに足す。各社のIRページは条件が付かないので条文が無い。

## 取り方

**配信されている構造化データ（XML・ICS・CSV・JSON など、機械が読む前提で形が決まっているファイル）を読むのは可。HTML を読み解いて日付を取り出す（スクレイピング）のはやらない。** 初回の公開だけでなく、この先も変えない。HTML はページの作りが変わると壊れ、発信者が想定していない読み方になる。

配信されている公表予定を読んでよいのは、次の4つを**すべて**満たすときだけ。

1. 発信者が公表予定を構造化データとして配信している
2. その取得を発信者が禁じていない（`robots.txt` と利用条件を読んで確かめる）
3. 「出典の可否」の表で「使う」になっている
4. 条件が `event.source_name` と `event.source_url` **だけで**満たせる。事前の連絡や、加工したことの明示など、手続きの要る出典は対象外

公表予定の日付を登録するのは転記で、編集・加工ではない。公共データ利用規約 1.1 が加工したときに求める「加工したこととその主体」の記載はこれに当たらないので、この規約を採っている出典は条件4を満たす。

| 出典 | 判断 | 理由 |
|---|---|---|
| 総務省統計局 | **読んでよい** | 4条件をすべて満たす（確認日 2026-08-12） |
| 内閣府 ESRI（GDP速報） | やらない | 条件1を満たさない。HTML の表のみ（確認日 2026-08-12） |
| 財務省貿易統計 | やらない | 同上（確認日 2026-08-12） |
| FRB（FOMC の日程） | やらない | 同上（確認日 2026-08-11） |
| BLS（米CPI・雇用統計） | やらない | 条件2を満たさない。ICS を配信しているが取得を禁じている（確認日 2026-08-11） |
| 各社のIRページ | **確かめていない** | 会社ごとにページが違う。使いたくなった会社があれば、そのときに1社ずつ確かめる |

- **実際に取り込んでいるのは、統計局が配信する10本のうち消費者物価指数の1本だけ**（`pnpm import:stat`）。ほかの9本は、使いたくなったときに1本ずつ中身を確かめる
- **4条件は可否を決めるだけで、取りに行く間隔は決めていない。** BLS が取得を禁じる理由「遅延を起こし、他の利用者が必要なときに情報を得るのを妨げうる」は、禁じていない出典にも当てはまる。間隔は `docs/guides/backup.md` §1.5 のとおり週1回で、決まった間隔での自動実行は入れていない（Issue #107）
- **手で登録する経路は無くならない。** 件数の一番多い決算発表日は、引き続き人が入れる

> 「出典の可否」と「取り方」は法律家によるものではない。判断の材料として書いている。

### プログラムからの取得

| 項目 | 内容 |
|---|---|
| 確認日 | 2026-08-12 |
| 確認したこと | 各サイトの `robots.txt` を取得した |
| 取得方法 | `curl -sS -w "http_code=%{http_code} size=%{size_download} content_type=%{content_type}"`。**下に貼ったのは返ってきたものそのもので、要約していない** |

#### `https://www.stat.go.jp/robots.txt`

`http_code=200 size=39 content_type=text/plain`

```
User-agent: *
Disallow: /library/opac/
```

これで全文（末尾に改行が無いため39バイト）。**公表予定の置き場（`/data/kouhyou/`）は `Disallow` に入っていない。**

#### `https://www.esri.cao.go.jp/robots.txt`

`http_code=404 size=5646 content_type=text/html`

**`robots.txt` は置かれていない。** 返ってきたのは内閣府の一般的な404ページで、`<title>404 Not Found - 内閣府</title>` と「指定されたページまたはファイルは存在しません。」が入っている。**方針が書かれたページではない。** BLS が 403 とともに方針文のページを返したのとは違う（→ 下記）。

#### `https://www.customs.go.jp/robots.txt`

`http_code=200 size=72 content_type=text/plain`

```
User-agent:*
Disallow:
Sitemap:https://www.customs.go.jp/sitemap_00.xml
```

これで全文。`Disallow:` の右が空なので、禁止しているパスは無い。

#### 読み取ったこと

**3つとも、取得を禁じる記述が見当たらなかった。** BLS（下記）とは正反対である。この結果を根拠に、「取り方」の節が「配信されている構造化データを読むのは可」と決めている。

ただし内閣府の「`robots.txt` が無い」は、**禁じていないことの証明ではない**。置いていないだけで、別の場所に方針が書かれている可能性は残る。内閣府は公表予定を配信しておらず「取り方」の条件1で対象外になるため、今のところ実害は無い。配信が始まったら、`robots.txt` 以外の場所も見て確かめ直す。

## 更新するとき

1. 条文のページを開き直す
2. 変わっていなければ確認日だけを新しくする
3. 変わっていれば、**古い引用を消さずに残し**、新しい引用を下に足して両方の確認日を書く。いつからいつまでどの条件だったかが分かる形にする
4. 条件が変わったら、「出典の可否」の表の可否と根拠も直す

**条文と一緒に、次の2つも開き直す。** どちらも条文ではないが、「取り方」の判断はこの2つに載っている。
