# 製品の決まり

コードに対応する場所が無い、製品としての判断をここに置く。コードの決まりはコードの隣のコメントと `CLAUDE.md`、出典の判断は [出典の利用条件](source-terms.md) にある。

## 何を作るか

持ち株に関連するイベント（決算・経済指標・テーマのイベント）をカレンダーで見る iOS アプリ。イベントは入力者が管理画面から人の手で登録する。

- **価値の中心は、テーマと銘柄とイベントの結び付け。** 決算日・権利確定日は証券会社のアプリに既にあり差がつかない。「このテーマのこのイベントでこの銘柄が動く」は自動では取れず、どこにも売っていない。人が入れる管理画面はつなぎではなく製品の中身である
- **カレンダーは最初の形で、製品の全体像ではない。** 将来は、持ち株を使った分析（似た持ち株の人が持っている銘柄・保有割合）へ広げる構想がある
- **株価・損益・チャート・売買は持たない。予測も助言もしない**

| 用語 | 識別子 | 意味 |
|---|---|---|
| 入力者 | `user` | 管理画面にサインインする人。アプリを使う人はアカウントを持たない |
| 銘柄 | `stock` | 市場とティッカーの組で1つに決まる株式 |
| テーマ | `theme` | 銘柄をまとめる札。階層は無い |
| テーマ所属 | `theme_stock` | テーマと銘柄の多対多 |
| イベント | `event` | カレンダーに出る出来事。対象（市場・テーマ・銘柄のどれか1つ）を自分の列に持つ |
| 持ち株 | — | アプリを使う人が選んだ銘柄。サーバーには置かず端末に持つ |

## 前提が動くと覆る判断

次の判断は、まだ確かめていない前提の上に載っている。前提が動いたら、この表から影響を見る。

| 判断 | 載っている前提 | 動いたら |
|---|---|---|
| 持ち株をサーバーに持たない | 使う人ごとに違うのはイベントの絞り込みだけ | 保有割合や、ほかの人の持ち株を集めて使う機能に着手する日に覆る。そのときサインアップ・アカウント削除・持ち株のサーバー同期を同じ PR でまとめて作る |
| 予測も助言もしない | 明示の合意は無い | 「似た持ち株の人の銘柄」機能を設計するときに決め直す（→ 下の「投資助言との境界」） |

**まだ分かっていない前提**: 開く頻度と見ている時間、想定する利用者の数、利用者の像、最初の形で確かめたい仮説。どれも使ってみれば測れるので、推測で埋めない。

## 初回の公開に入れないもの

| 項目 | 理由 |
|---|---|
| リモートのプッシュ通知 | サーバー側が重い。端末内の通知で足りるかを先に確かめる |
| ホーム画面のウィジェット | 「開いて見る」使い方を確かめるのが先 |
| 標準のカレンダーへの書き出し | 標準のカレンダーに出すならこのアプリが要らない可能性がある。確かめてから決める |
| 銘柄から引く画面（2つ目のタブ） | 1つ目のタブが動いてから足せる |
| 重要度以外の絞り込み・ミュート・テーマの階層 | 使う人が自分だけの間は要らない |
| 広告 | 使う人が自分だけの間は収入が0円なのに、追跡の同意画面・App Privacy の申告・SDK・審査の手間だけを先に負う |

月グリッドを主画面にしたのは開発者の判断で、金融のアプリは日付順の一覧に揃っている（Stock Events・TradingView・Investing.com など）。一覧が要るようになったら、タブを1つ足せば並べられる。

## 収益化

**広告（AdMob のバナー）から始める。** 入れるのは、自分以外に使う人がついてから。

- **選んだ理由は、本名を出さずに始められること。** 1人あたりの収益は課金のほうが2〜5倍高い（Issue #17 の試算）。課金には特定商取引法の表示が要り、**氏名は省略できない**（個人は戸籍上の氏名か登記した商号）。住所と電話番号は「請求があれば遅滞なく出す」と書けば省ける（消費者庁の通信販売広告 Q&A）。広告だけなら消費者への販売が無いので、この表示は要らない
- **測る前に決めた理由**: 測って動くのは広告の数字だけで、置けるのはバナーだけ（見る時間が数十秒のアプリに全画面の広告は置けない）。数割動いても課金との順位は入れ替わらない
- **課金へ切り替える条件**: 広告では固定費（Apple Developer Program 年 US$99 とサーバー代）を回収できないと測って分かり、かつ使う人がついているとき。そのとき本名を出すことを受け入れる
- **無料枠が「非商用に限る」サービスは選べない**（Vercel Hobby は広告・寄付まで商用に数える）。いまの Netlify と Supabase の無料プランは商用に使える（Issue #16）

## 投資助言との境界

投資助言・代理業の登録が要るのは、おおむね **①報酬を得て ②契約に基づき ③その人に合わせた助言をする** 場合とされる。誰でも同じ内容を得られる情報は、登録の要らない側に整理される。

| 要素 | いまのカレンダー | 将来の「似た持ち株の人が持っている銘柄」 |
|---|---|---|
| その人に合わせているか | **いいえ。** 全員に同じ予定が出る | **はい。** 登録した銘柄で出る中身が変わる |
| 報酬 | **無い。** 無料 | 有料の機能にすれば **ある** |
| 契約 | 無い | 無い |

- **危ないのは「その人に合わせた提示」と「有料」がそろったとき。** 「似た人の銘柄だけ有料」は、対価とその人向けの提示が直結するので最も危うい。広告の収入だけなら弱いと考えられるが、**確かめていない**
- **言葉づかいで性格が変わる。** 「6920 を買うとよいでしょう」は助言。「似た持ち株の人の62%が 6920 を持っています」は事実の提示で、判断は本人がする
- **この機能の設計に着手するときに、①有料にするか ②どちらの言葉づかいにするか を先に決め、専門家に確かめる。** それより前は要らない
